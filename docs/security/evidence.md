# Security review evidence

Phase 4 epic "Security review" (roadmap: threat-model walkthrough, pen-test checklist, evidence pack; exit gate: findings closed). Reviewed commit: `a70f63f` (main before the review). Method: [threat-model.md](threat-model.md), then the attacks in [pentest-checklist.md](pentest-checklist.md) written as automated tests; a finding is an attack that worked, or a control the design promises that the running code did not provide.

## Summary

| Severity | Found | Fixed | Accepted | Open |
| -------- | ----- | ----- | -------- | ---- |
| High     | 1     | 1     | 0        | 0    |
| Medium   | 11    | 11    | 0        | 0    |
| Low      | 24    | 12    | 7        | 5    |
| Total    | 36    | 24    | 7        | 5    |

F-01 to F-18 are the Phase 4 review; F-19 to F-36 are a second, independent review of PRs #93 to #99 (below). The Phase 4 review found no High: its database policies held under a fuzz of every definer function and under every wall and guest test. The second review found one (F-23), in a read policy that predates those PRs. Medium findings are controls the design requires that were absent, unwired or too weak in a way an attacker with a stolen session, a connector or a proxy position could use.

## Re-running the review

```sh
pnpm install --frozen-lockfile && pnpm build
# the database layer, including the cross-tenant function fuzz (P-01), residue scan (P-03)
pnpm --filter @legallabs/db test
# the API layer: P-05 to P-12 and the earlier suites
pnpm --filter @legallabs/api test
```

Both start a private Postgres 17 (`initdb`/`pg_ctl` on the PATH, or `TEST_DATABASE_URL`). When a migration or an RLS policy is added, P-01 and `rls.test.ts` cover it without edits: P-01 enumerates the functions and tables itself.

## Residual risk

1. A person with a valid session and the right to run SQL as the app role bypasses the synced-vault guard and the API-scope setting (F-07). The API has no such path; a new raw SQL route would be the way in.
2. Strictest-scope retention is undecided (F-16); until it is, owners must read the policy list, not infer from the workspace policy alone.
3. The tool executor and policy engine are covered end to end against a fake MCP server (`api/e2e/runs.test.ts`, `api/agents/tools.test.ts`), not against a real third-party server; MCP session ids, SSE replies and OAuth connectors are not supported.
4. Single process in-memory limiters (F-15).
5. Everything marked not built above, in particular ADM-007 allow-listing and the injection suite, which matter most for a compromised-account or malicious-document actor.
